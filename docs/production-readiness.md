# 유료 운영 준비 상태

2026-09-18 기준. **PR9까지 운영 웹/API와 DB0017 배포를 완료했지만, 원문 전체 완료나 유료 시험 운영 가능 상태는 아니다.** 애플리케이션 환경은 staging이며 실제 청구·제작 출력·삭제/GC 실행 게이트는 닫혀 있다. 계약·ICC 인쇄 엔진·보관/지원·서비스 주문·정책·브랜드 글꼴·지표 코드도 이번 운영 배포에 포함됐다. 배포 후 운영 등록 글꼴·SVG·출력3건/8페이지와 새 논리 백업/격리 복원을 확인했다. 모든 메뉴·역할의 실증 완료를 뜻하지 않는다.

- PR9 `21e5070c14f1aa377aab67a7e68eec7d177a97fb`는 [CI35274845908](https://github.com/phoenixai-sw/phoenix-packaging/actions/runs/35274845908)에서 통과한 `a40f38e`와 내용이 같다. Python844·JS78·타입·계약 drift·production 빌드가 통과했고, main 웹/API 배포가 모두 성공했다.
- DB0011~0017 순방향 이행·비공개 버킷 MIME 추가·전체 테이블 RLS를 확인했다. 실행 플래그는 OFF를 유지했으며 고객 데이터 비교의 3개 차이는 heartbeat·지갑 잠금 제어 필드였다.

## 마지막 원문 누락 보완과 남은 확인

확인했던 세부 누락은 아래처럼 보완해 PR9에 배포했다. 자동시험·로컬 실증과 아직 수행하지 않은 운영·제조 검수를 구분한다.

- §17(원문460행)의 **정화한 SVG 수입**을 구현해 배포했다. 정적 도형을 정화해 PNG로 표시하며 외부 참조·스크립트·SVG 글자를 차단한다. 새48개/업로드·편집 ZIP 포함80개 회귀, 실제 로컬1200×900 SVG 업로드→비율 유지 배치/저장→정화 원본·PNG 포함 ZIP 완료를 확인했다. 벡터 도형 편집·SVG 글자 재조판은 지원하지 않는다. [범위와 검증](svg-import.ko.md)
- §18(468행)의 **완료 파일 승인 철회 안내**를 연결해 배포했다. 출력 당시 도면/프로필 ID로 현재 상태와 최신 고객 공개 사유만 조회하며, 내부 감사 사유를 노출하지 않는다. 실제 worker ZIP 생성→철회→상세/목록 안내·타 조직 차단·파일 해시/저장 결과 보존과 100개 이력의 고정2회 조회를 포함한 서버3개, 프런트 상태 시험2개가 통과했다. 운영 제작 파일의 실제 철회 사례는 없다.
- §8.1(175행)의 **draft→review→approved 검토 단계**를 추가해 배포했다. 관리자 검토 요청과 감사 기록, review를 거치지 않은 승인 차단, 승인된 버전만 철회하는 규칙을 포함해 관련17개 시험이 통과했다. 실제 로컬 UI에서 초안→검토중, 증빙/담당자/확인 기록이 없을 때 승인 비활성을 확인했다(승인 실행0). 검토 공개와 제조 승인 상태는 별개다.
- 전체 HTTP 생성 계약은 있지만 일부 기존 수동 `Project` DTO·`api<T>` 호출이 남는다. 모든 프런트 호출을 생성 타입으로 정적 검증했다고 표현하지 않는다.

PDF/X·별색·화이트 등은 §11.2(250·256행)의 capability 비교와 미지원 제작 차단을 따른다. 이들을 지원하지 않는다는 이유만으로 원문이 초기부터 모든 출력 형식을 필수로 요구했다고 해석하지 않는다. 전체 조직 삭제·unknown GC·ZIP 재가져오기·자동 전문가 배정도 실제 제한으로 공개하되 원문에 없는 초기 완료 조건을 새로 만들지 않는다.

## 배포 후 추가 검수와 유료 운영 전 조건

1. **완료한 범위:** 운영 QA `cfd10093…`의 등록 글꼴·SVG·저장본5 출력3건/8페이지와 DB0017 백업63테이블·338행·39객체의 격리 앱 재열기를 확인했다. 서비스 접수·보관 삭제 등 운영 변경과 모든 역할 실증은 이 결과로 대체하지 않는다.
2. 비공개 버킷 MIME 추가, 실제 운영 정적 TTF 업로드/브랜드 연결 및 Linux SVG 업로드·변환을 확인했다. 운영 글꼴 권리, ICC의 변환·PDF 포함 권리, ZIP 원본 재배포 권리는 각각 확인한다.
3. Toss 테스트 상점의 실제 카드 등록·승인·갱신·취소·조회/웹훅을 검증한다. 라이브 자동결제 계약, VAT·환불·갱신 고지·개인정보/이용조건을 확정한다.
4. 공개 기본 규격 검사와 실제 제조 승인을 구분한다. 실제 도면·재질·ICC/출력 조건에 맞는 표본을 검수하고 제조사 제출10건·기술/미적 반려 구분·실물 품질을 기록한다. 공개 수치만으로 제조 승인을 만들지 않는다.
5. 운영 PostgreSQL/PITR 복구와 Storage 복원을 별도 환경에서 실증하고 담당자·복구시간을 정한다. 네이티브 Windows IME 및 아직 실기 확인하지 않은 모바일 조작도 별도 검수한다. 운영390×844의 글꼴 등록·서비스·보관 화면은 가로 넘침 없이 표시됐고 서비스 선택에 따른 가격/필수 항목 변경·보관 상태와 요청 내역 조회를 확인했다. 접수/삭제는 실행하지 않았으므로 전체 모바일 업무·모든 역할의 실증은 별도다.

삭제/GC 플래그는 이번 배포 후에도 OFF다. 환경 변경과 스토리지 삭제는 현재 코드 검증과 별개의 운영 결정이다. Google·Toss 연결 안내는 [owner-setup](owner-setup.ko.md), 전체 개별 항목은 [원문 추적표](spec-completion-tracker.ko.md)를 따른다.

## 서버 게이트와 지원 제한

실제 결제는 production 환경, 라이브 키·MID, `BILLING_POLICY_APPROVED`, `LIVE_BILLING_ENABLED`와 요금 정책의 라이브 허용이 모두 유효해야 한다. 테스트·모의 결제는 실제 고객 획득으로 집계하지 않는다.

제작은 `ENABLE_PRODUCTION_EXPORT`, `OPERATING_POLICY_APPROVED`, 승인 도면/프로필/증빙, 정확한 치수·재질, 최신 리비전·전체 면/고객 문구 확인, 상품 식별·지갑 검사와 실제 출력 capability를 모두 통과해야 한다. 기존 RGB 엔진과 PR9에 배포한 ICC CMYK·윤곽선·분리 CUT/FOLD의 지원 범위를 구분한다. 시험 ICC는 제작에 사용할 수 없으며 CMYK 출력시험 ZIP에는 검토 표기를 남긴다. PDF/X·별색·화이트·오버프린트 등 미지원 조건을 차단하는 것은 원문 §11.2가 허용한 동작이며 지원 완료라는 뜻이 아니다.

`RETENTION_CUSTOMER_DELETE_ENABLED=false`, `STORAGE_GC_DELETE_ENABLED=false`가 기본이다. true여도 승인 범위·hold·백업·현재/과거 참조·SHA가 모두 유효해야 실행한다. 조직/프로젝트 전체 삭제는 검토 접수만 지원한다.

## 백업·복원과 롤백

`scripts/backup-platform.py`는 연결된 앱 테이블과 Storage 객체를 암호화하고 격리 SQLite에서 값·외래키·파일 해시·앱 재열기를 확인한다. 배포 전41테이블·293행·33객체에 이어 **DB0017 배포 후63테이블·338행·39객체**도 백업·복원을 통과했다. 후자의 앱에서8프로젝트·46저장본·15자산·19작업·12출력·16원장(API16), 장면 자산 연결15개를 확인했다. 원본 DB를 사용하지 않고 외부 네트워크를 차단한 오프라인 소유자 세션이며 로컬 세션/크레딧 만료 갱신만 발생했다. 이 복원 시험은 Google 실로그인이나 PostgreSQL 물리/PITR 복구 검증이 아니다.

이 도구는 PostgreSQL 물리 백업/PITR을 대체하지 않는다. DB 백업에 Storage 객체가 자동 포함된다고 가정하지 않는다. 키는 백업 폴더 밖에 두고 Git에 기록하지 않는다.

롤백은 호환되는 직전 웹/API/worker 배포를 함께 검토한다. 데이터가 있는 DB에 자동 downgrade하지 않고, 백업·호환성 확인 후 순방향 migration을 우선한다. 기존 환경 갱신은 `scripts/update-cloud-env.py`를 사용한다.
