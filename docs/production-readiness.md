# 유료 운영 준비 상태

현재는 P0–P1 개발 시험판이다. Supabase Pro 프로젝트 비용 승인은 월 약 US$10 MICRO 기본 컴퓨트 범위이며 사용량 초과나 상위 사양 증설의 별도 승인을 의미하지 않는다.

## 연결 완료

- GitHub 비공개 저장소와 Vercel 웹·API 프로젝트 구성
- Supabase Pro 조직 전용 서울 프로젝트와 PostgreSQL·비공개 Storage
- 암호화 환경변수, 명시적 staging 환경, 제작·결제 비활성

## 운영 전 필요한 항목

- 제조사 도면 사용권·치수·재질·인쇄 프로파일·승인 증빙
- 실제 출력 입고, 한글 줄바꿈·색상·바코드의 실물 검증
- 이미지 API 키·모델·원가·오류 복구 검증
- PG 테스트 및 운영 계약, 환불·보관·요금 정책
- 이메일 발송 제공자와 도메인 인증
- 유료 서비스 개인정보처리·이용조건 확정
- 백업 별도 환경 복원 실증 및 모니터링
- 조직/좌석 관리와 과금 원장 등 P2–P3 구현

## 백업과 복원 절차

1. Supabase의 해당 프로젝트 Database Backups에서 최신 백업과 보존 정책을 확인한다. 데이터베이스 백업만으로 Storage 객체 파일이 복원되지는 않는다.
2. PostgreSQL 전체 스키마/데이터의 논리 백업과 비공개 `phoenix-private` 버킷 객체를 같은 시점 기준으로 별도 안전한 저장소에 백업한다. 객체별 SHA256 manifest를 보존한다.
3. 새로운 복구 프로젝트에 SQL 백업과 버킷 객체를 복원한 뒤 `alembic upgrade head`를 수행한다.
4. 원본 환경을 수정하지 않고 복구 환경에서 프로젝트 재열기·한글 문구·자산·리비전·PDF 링크를 대조한다.
5. 복원 검증을 통과한 경우에만 새 DATABASE_URL/Storage 연결로 배포한다.

위 절차의 실제 별도 환경 복원은 아직 미실시다. AC31 통과로 집계하지 않는다.

## 롤백

Vercel의 직전 정상 배포로 웹/API를 함께 되돌린다. 데이터가 존재하는 DB에서 migration downgrade를 자동 실행하지 않는다. 변경 호환성과 백업을 확인한 뒤 순방향 복구 migration을 우선한다. 비밀값은 Git에 되돌리지 않고 해당 서비스의 암호화 환경변수로 관리한다.
