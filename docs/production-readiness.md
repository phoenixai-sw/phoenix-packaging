# 유료 운영 준비 상태

2026-09-18 기준. **원문 전체 완료나 유료 시험 운영 가능 상태가 아니다.** PR7·PR8까지 웹/API가 운영에 배포됐으며 애플리케이션 환경은 staging이다. 실제 청구와 제작 출력 게이트는 닫혀 있다. 현재 `codex/spec-completion-ops`의 계약·ICC 인쇄 엔진·보관/지원·서비스 주문·정책·브랜드 글꼴·지표는 **로컬 검증 중인 배포 후보**다. 이 문서의 후보 기능을 운영 제공 완료로 읽지 않는다.

## 이미 확인한 운영 범위

- GitHub 비공개 저장소, Vercel 웹/API, Supabase Pro 서울의 DB·비공개 Storage를 연결했다.
- 전용 Google OAuth의 실제 운영 로그인과 `ADMIN_EMAILS` 관리자 접근을 확인했다. 비밀번호·인증메일·Resend 절차는 후속 지시로 제거했다. Google 설정을 다시 미완료로 표시하지 않는다.
- 실제 Sunburst/high 생성·글자 제거, 크레딧 정산, 검토 PDF와 편집 ZIP의 저장/다운로드 사례가 있다. 새 모델·품질 조합 전부의 유료 품질 시험을 완료한 것은 아니다.
- PR8 `7f4e81f`의 서버612개·프런트66개·타입검사·빌드·CI, 운영 ZIP12파일·9.8MiB의 해시를 확인했다. 현재 후보의 시험 수나 배포 결과와 구분한다.

## 마지막 원문 누락 보완과 남은 확인

세부 누락을 확인해 아래처럼 보완하고 있다. 후보 배포와 실제 검수를 완료 상태로 앞당겨 표시하지 않는다.

- §17(원문460행)의 **정화한 SVG 수입**을 후보에 구현했다. 정적 도형을 정화해 PNG로 표시하며 외부 참조·스크립트·SVG 글자를 차단한다. 새48개/업로드·편집 ZIP 포함80개 회귀, 실제 로컬1200×900 SVG 업로드→비율 유지 배치/저장→정화 원본·PNG 포함 ZIP 완료를 확인했다. 벡터 도형 편집·SVG 글자 재조판은 지원하지 않는다. [범위와 검증](svg-import.ko.md)
- §18(468행)의 **완료 파일 승인 철회 안내**는 후보에 연결했다. 출력 당시 도면/프로필 ID로 현재 상태와 최신 고객 공개 사유만 조회하며, 내부 감사 사유를 노출하지 않는다. 실제 worker ZIP 생성→철회→상세/목록 안내·타 조직 차단·파일 해시/저장 결과 보존과 100개 이력의 고정2회 조회를 포함한 서버3개, 프런트 상태 시험2개가 통과했다. 운영 제작 파일의 실제 철회 사례는 없다.
- §8.1(175행)의 **draft→review→approved 검토 단계**를 후보에 추가했다. 관리자 검토 요청과 감사 기록, review를 거치지 않은 승인 차단, 승인된 버전만 철회하는 규칙을 포함해 관련17개 시험이 통과했다. 검토 공개와 제조 승인 상태는 별개다.
- 전체 HTTP 생성 계약은 있지만 일부 기존 수동 `Project` DTO·`api<T>` 호출이 남는다. 모든 프런트 호출을 생성 타입으로 정적 검증했다고 표현하지 않는다.

PDF/X·별색·화이트 등은 §11.2(250·256행)의 capability 비교와 미지원 제작 차단을 따른다. 이들을 지원하지 않는다는 이유만으로 원문이 초기부터 모든 출력 형식을 필수로 요구했다고 해석하지 않는다. 전체 조직 삭제·unknown GC·ZIP 재가져오기·자동 전문가 배정도 실제 제한으로 공개하되 원문에 없는 초기 완료 조건을 새로 만들지 않는다.

## 운영으로 옮기기 전

1. 후보 코드의 전체 회귀·CI·실제 UI/PDF/ZIP 결과를 확정하고, 현재 운영 데이터의 암호화 백업과 격리 복원을 확인한다. worker를 잠시 중단한 뒤 `0011`~`0017`을 순방향 적용하고 같은 코드의 API/worker/web를 배포한다. 현재 운영 DB0010 이후 변경이다.
2. 비공개 본체/업로드 버킷에서 `font/ttf`를 허용하고 글꼴 직접 업로드→서버 검증→불변 원본 보관을 확인한다. 운영 글꼴 권리, ICC의 변환·PDF 포함 권리, ZIP 원본 재배포 권리는 각각 확인한다.
3. Toss 테스트 상점의 실제 카드 등록·승인·갱신·취소·조회/웹훅을 검증한다. 라이브 자동결제 계약, VAT·환불·갱신 고지·개인정보/이용조건을 확정한다.
4. 공개 기본 규격 검사와 실제 제조 승인을 구분한다. 실제 도면·재질·ICC/출력 조건에 맞는 표본을 검수하고 제조사 제출10건·기술/미적 반려 구분·실물 품질을 기록한다. 공개 수치만으로 제조 승인을 만들지 않는다.
5. 운영 PostgreSQL/PITR 복구와 Storage 복원을 별도 환경에서 실증하고 담당자·복구시간을 정한다. 네이티브 Windows IME 및 아직 실기 확인하지 않은 모바일 조작도 별도 검수한다.

삭제/GC 플래그는 이번 후보 배포만으로 켜지 않는다. 환경 변경과 스토리지 삭제는 현재 코드 검증과 별개의 운영 결정이다. Google·Toss 연결 안내는 [owner-setup](owner-setup.ko.md), 전체 개별 항목은 [원문 추적표](spec-completion-tracker.ko.md)를 따른다.

## 서버 게이트와 지원 제한

실제 결제는 production 환경, 라이브 키·MID, `BILLING_POLICY_APPROVED`, `LIVE_BILLING_ENABLED`와 요금 정책의 라이브 허용이 모두 유효해야 한다. 테스트·모의 결제는 실제 고객 획득으로 집계하지 않는다.

제작은 `ENABLE_PRODUCTION_EXPORT`, `OPERATING_POLICY_APPROVED`, 승인 도면/프로필/증빙, 정확한 치수·재질, 최신 리비전·전체 면/고객 문구 확인, 상품 식별·지갑 검사와 실제 출력 capability를 모두 통과해야 한다. 기존 운영 RGB 엔진과 새 후보의 ICC CMYK·윤곽선·분리 CUT/FOLD를 구분한다. 시험 ICC는 제작에 사용할 수 없으며 CMYK 출력시험 ZIP에는 검토 표기를 남긴다. PDF/X·별색·화이트·오버프린트 등 미지원 조건을 차단하는 것은 원문 §11.2가 허용한 동작이며 지원 완료라는 뜻이 아니다.

`RETENTION_CUSTOMER_DELETE_ENABLED=false`, `STORAGE_GC_DELETE_ENABLED=false`가 기본이다. true여도 승인 범위·hold·백업·현재/과거 참조·SHA가 모두 유효해야 실행한다. 조직/프로젝트 전체 삭제는 검토 접수만 지원한다.

## 백업·복원과 롤백

`scripts/backup-platform.py`는 연결된 앱 테이블과 Storage 객체를 암호화하고 격리 SQLite에서 값·외래키·파일 해시·앱 재열기를 확인한다. 최신 확인된 운영 표본은41테이블·293행·33객체다. 후보는 글꼴 원본과 장면 참조의 암호화 백업/복원, 백업 pin과 삭제/GC 경합을 별도 시험했다. 이전 백업 수치를 이번 후보 전체 운영 복원 증거로 사용하지 않는다.

이 도구는 PostgreSQL 물리 백업/PITR을 대체하지 않는다. DB 백업에 Storage 객체가 자동 포함된다고 가정하지 않는다. 키는 백업 폴더 밖에 두고 Git에 기록하지 않는다.

롤백은 호환되는 직전 웹/API/worker 배포를 함께 검토한다. 데이터가 있는 DB에 자동 downgrade하지 않고, 백업·호환성 확인 후 순방향 migration을 우선한다. 기존 환경 갱신은 `scripts/update-cloud-env.py`를 사용한다.
