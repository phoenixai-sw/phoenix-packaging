# 브랜드 글꼴 — 정적 TTF

브랜드 보관함의 **팀 글꼴 보관함 → 검사 후 등록**에서 파일과 라이선스를 보관하고, **브랜드 편집 → 새 문구에 허용할 등록 글꼴**에서 사용할 파일을 선택한다. 해당 브랜드를 프로젝트에 연결하면 편집기의 문구 속성에서 글꼴을 선택할 수 있다. 파일의 실제 두께를 사용하며 임의로 굵게 만들지 않는다. 기본 Noto Sans KR 400/700은 이전과 동일하다.

업로더는 웹 제공·편집·PDF 포함·인쇄·윤곽선 사용 권한과 출처·권리자·라이선스 원문을 기록한다. **편집 ZIP으로 원본 글꼴을 전달하는 권한은 별도 항목**이다. 전달 권한이 확인되지 않은 글꼴이 사용되면 ZIP 생성을 차단한다. 권리 기록은 사용자의 진술이며 플랫폼이 법적 이용권을 인증했다는 뜻은 아니다.

정적 `glyf` TrueType TTF만 받는다. 파일당 20MiB, 팀 글꼴 보관 100MiB·200개가 한도이며 로컬 전송 한도는 서버 설정에 따라 낮을 수 있다. 가변·CFF·컬러 글꼴과 비정상·과도한 윤곽선은 거부한다. [OpenType OS/2 규격](https://learn.microsoft.com/en-us/typography/opentype/spec/os2)에 따라 파일 내부 제한도 확인한다. 현재 편집·부분 포함 방식에 맞는 `fsType=0` 또는 `8`만 허용하며, 이 검사도 실제 라이선스를 대신하지 않는다.

파일과 권리 기록은 불변이다. 브랜드의 허용 목록에서 제거하면 **새 선택만** 제한되고 이미 저장된 문구·과거 리비전·복원본은 기존 글꼴을 유지한다. 서버와 브라우저는 동일한 원본 SHA를 확인하며, PDF/3D/캔버스는 해당 파일의 문자 폭과 기준선을 사용한다. 원본 누락·손상·두께 불일치·누락 글리프는 다른 글꼴로 대체하지 않고 알린다. 복잡한 조형이 필요한 조합 자모·결합문자·아랍/히브리 문자는 현재 검증 범위 밖이며 출력이 차단된다.

편집 ZIP은 허용된 원본 TTF와 해당 라이선스를 함께 담고, 문구의 `font_asset_id`를 보존한다. 암호화 애플리케이션 백업에도 원본 글꼴이 포함된다. ZIP 재가져오기 UI가 새로 추가된 것은 아니다.

운영 반영에는 migration `0016_font_assets`와 비공개 본체/업로드 버킷의 `font/ttf` 허용이 필요하다. 직접 업로드는 임시 격리 경로로만 허용하고 서버 검증 후 별도 불변 경로에 복사한다. 원본 글꼴 삭제 API는 제공하지 않으며, 임시 업로드 정리는 보관·백업 보호를 따른다.

이 문서는 새 작업 폴더의 구현·자동 시험 범위를 설명한다. 운영 배포나 실제 고객 글꼴의 권리 검증 완료를 뜻하지 않는다.
