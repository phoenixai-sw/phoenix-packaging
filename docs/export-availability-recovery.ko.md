# 출력 파일 무결성 확인과 손실 처리

검토 PDF, 편집 ZIP, CMYK 시험 ZIP, 제작 ZIP에 같은 보관 무결성 확인을 적용한다. 원문 §13.1의 완료 후 파일 소실 상황을 다루며, 이 기능이 제조사 승인을 만들거나 유료 작업을 자동 재생성하지는 않는다.

## 다운로드와 상태

- 기존 조직·작업 공간·원본 자산·글꼴 권한을 확인한 뒤, 저장 파일을 제한된 크기로 읽고 서버에 동결한 SHA-256 및 크기와 대조한다. 클라우드에서는 검증 후 60초 서명 링크로 연결하며 파일 전체를 웹 응답 본문으로 프록시하지 않는다.
- 최초 소실·손상 관측은 `suspect`다. 완료/차감 이력은 유지하지만 다운로드 링크를 숨기고 직접 요청도 차단한다.
- 같은 소실·손상 증거가 **5분 이상 간격의 두 번 관측**에서 일치하면 확정한다. 작업자는 한 번에 기본 1개를 확인하고, 정상 파일 재점검은 24시간 이후다.
- 타임아웃, 권한 실패, 불명확한 404는 `temporarily_unverified`다. 보상하지 않고 기존 완료 이력을 유지하며, 이전 의심의 연속 관측을 끊는다. Supabase의 객체 없음 응답도 독립된 권한 있는 버킷/객체 목록 확인이 추가로 성공해야 소실 관측으로 취급한다.
- 과거 파일에 신뢰할 해시 기준이 없으면 미확인 상태로 닫힌다. 없는 근거를 발명하여 다운로드 허용이나 보상을 하지 않는다.

## 확정 손실 후

| 결과 | 동작 | 과금/재출력 |
|---|---|---|
| 무료 검토 PDF·편집 ZIP·CMYK 시험 ZIP | 작업을 실패로 표시하고 기존 재시도 메뉴를 제공 | 저장본을 유지하여 무료 재시도. 현재 접근 권한·프로필 조건 재검사 |
| 차감된 제작 ZIP | `unavailable`로 전환하고 다운로드·단순 재시도 차단 | 기존 차감의 배분별 보상 함수를 한 번만 실행. 새 제작은 현재 승인과 새 견적 필요 |
| 이미 무료였던 제작 재출력 ZIP | `unavailable`로 전환 | 복원할 차감이 없으므로 보상 0. 원래 유료 제작 권한은 유지 |
| 소유자 요청으로 삭제 중/삭제 완료 | 기존 삭제 상태 유지 | 파일 손실 보상에서 제외 |

유료 제작 권한 행과 원장·영수증·원본 저장본은 삭제하지 않는다. 손실이 보상된 원래 유료 권한은 `compensated`로 명시적으로 전환하고 감사 기록을 남긴다. 따라서 다음 제작은 새 유료 견적을 사용하며, 미리 발급받은 무료 견적도 변경 오류로 거부된다. 이미 예약된 무료 작업 역시 게시 직전에 권한을 다시 확인하므로 보상 이후 무료 결과를 공개하지 않는다. 제작 게시와 손실 보상은 조직→지갑→개별 행 순서로 잠금을 잡는다.

파일 결과의 공개 manifest는 유지하며 내부 `_integrity`에 관측 기록을 둔다. API에는 이 내부값이나 보관 키를 노출하지 않고 `availability`만 제공한다. 제조사 입고 기록은 별도 이력으로 보존된다.

## 백업과 검증 범위

확정 소실/손상 파일은 다음 백업의 객체 복사 대상에서 제외하되 DB의 저장본·원래 파일 식별자·보상/감사 기록은 보존한다. 백업 manifest의 `known_unavailable_exports`에 누락 사유를 기록한다. 격리 복원 앱에서도 해당 파일이 410이며 다운로드 링크가 없음을 검사한다. 원본 저장소 파일을 삭제하거나 손상 바이트를 정상 원본으로 대체하지 않는다.

검증은 격리된 SQLite와 로컬 저장소 및 모의 클라우드 오류를 사용한다. 실제 PostgreSQL 병렬 부하·클라우드 장애 주입은 수행하지 않았다. 새 회귀는 `services/api/tests/test_export_reconciliation.py`에 있으며, 동시 중복 보상, 제작 게시 직전 권한 변경, 확정/불명확 오류, 세 가지 무료 출력 재시도, 조직 격리, 보관 삭제 예외, 과거 해시 부재와 백업 복원 경계를 포함한다. 제조 승인·운영 데이터·유료 API 호출은 변경하지 않았다.
