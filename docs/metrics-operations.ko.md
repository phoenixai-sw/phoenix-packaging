# 내부 성과·원가 계측 (§18)

이 기능은 앱 내부 서버 기록과 관리자 운영 기록으로 성과를 계산한다. 외부 광고·분석 SDK를 사용하지 않으며 고객 이메일, 디자인 원문, 상품 문구, 프롬프트, 입력한 키, 포인터 좌표를 계측 데이터로 보내지 않는다. 유료 고객 5곳·실제 작업 10건·기술적 입고 통과 90%라는 검증 목표를 달성했다고 표시하는 기능은 아니다.

## 실제 기록 지점

| 원문 이벤트 | 기록 지점과 중복 기준 |
|---|---|
| signup_completed / trial_granted | Google 신규 계정 생성 / 실제 signup-trial 버킷. 계정·버킷 ID별 1회 |
| project_created / brief_completed | 프로젝트 생성 / 필수 상품명·브랜드명이 채워진 저장. 프로젝트별 1회. 별도 인터뷰 완료를 뜻하지 않음 |
| generation_succeeded / generation_failed | AI 하위 결과 게시·정산 / 제공자 시도 실패·권한 철회·예산 차단·worker 만료. 성공은 하위 결과별, 실패는 시도·실패 원인 단계별 |
| text_edited | 새 장면 저장 시 면·객체별 문구 변경 개수. 원문을 저장하지 않음 |
| all_faces_reviewed / preflight_failed | `/preflight`의 사용자가 확인한 면 목록 / 검수 오류. 저장본·검수 종류·오류 수를 기준으로 중복 제거. 브라우저가 신고한 검토이며 실제 사람의 독해를 증명하지 않음 |
| production_export_succeeded | 검토·시험 출력이 아닌 정상 제작 결과의 게시 및 크레딧 CAPTURE와 같은 트랜잭션 |
| credits_insufficient | 인증·CSRF가 확인된 실제 402 오류가 business transaction에서 롤백된 뒤 별도 기록. 요청 ID별 1회 |
| topup_paid / subscription_paid / renewal_paid | 결제 서버 재확인이 끝난 주문·결제 정산과 같은 트랜잭션. 상향 결제는 신규 구독으로 기록하지 않음 |
| printer_accepted / printer_rejected | 인쇄소 입고 회신 기록. test/manufacturer 출처와 기술/미적 반려 구분을 남김 |

이벤트 집계는 제공자와 회신 출처별로 나눠 fixture/test를 실사용 성과와 구분한다. 알 수 없는 이벤트명·속성은 거절한다. 이벤트를 자유롭게 게시하는 고객 API는 없다. 이벤트의 tenant/project/job/revision 연결은 실제 DB 행과 대조하며 연결이 존재하지 않는 항목은 null이다. 불변 이벤트 키와 비용 정정 키에 DB unique 제약을 둔다. 기존 이력 중 당시 수집하지 않은 신규 가입 UTM, 문구 수정, 활동 시간은 만들지 않는다. 기존 체험 버킷은 재로그인 시 원래 버킷 생성 시각으로 한 번 연결될 수 있다.

## 유입과 최초 실결제

랜딩 페이지에서 세션 첫 유입을 `sessionStorage`에 저장한다. source와 medium은 허용된 그룹만 받고, 나머지는 `other`로 바꾼다. campaign은 제한된 영문·숫자·밑줄·하이픈만 받으며 **DB에는 SHA-256 해시만 보존**한다. 전체 URL·referrer·검색 문자열은 보존하지 않는다. 캠페인 ID에 고객 개인정보를 넣지 않는다. UTM은 클라이언트가 신고한 유입 참고치이며 결제 증빙이나 광고 플랫폼 검증을 의미하지 않는다.

신규 Google 가입 시 tenant에 최초 유입을 연결하며 기존 계정의 로그인으로 덮어쓰지 않는다. 조회 기간에 가입한 조직을 묶고 종료일 이전 체험과 첫 구독 실결제를 비교한다. 전체 결제 이력에서 최초 `toss_live` + 검증된 승인 이력(`DONE`·`CANCELED`·`PARTIAL_CANCELED`) + `subscription`만 신규 고객으로 센다. 갱신·충전·상향·재구독을 신규 고객으로 중복 집계하지 않는다. 모의·Toss test·미지원 제공자는 별도 제외 건수다. 후속 환불은 최초 승인 전환을 소급 삭제하지 않고 별도 환불 이벤트 수로 표시한다. 최초 PG 조회가 이미 취소 상태여도 검증된 approvedAt의 과거 승인을 보존한다. 이는 순매출 보고서가 아니다.

## 경과 시간과 활동 추정

프로젝트 생성부터 첫 정상 제작 출력까지의 서버 경과 시간과 브라우저 활동 추정치를 별도 칼럼으로 보여준다. 검토 PDF·제조 시험 ZIP은 정상 제작 출력에 포함하지 않는다. 보고서 종료일 뒤의 결과도 포함하지 않는다.

`POST /v1/metrics/activity {project_id}`는 본인 활성 로그인·프로젝트 ACL·owner/editor 역할·CSRF·`X-Editor-Lease`를 모두 요구한다. 브라우저는 활성 편집창에 실제 입력이 있었던 경우에만 30초 간격으로 요청하며 텍스트나 키 값을 보내지 않는다. 서버는 시간을 직접 계산한다. 첫 신호 0초, 연속 신호 간격 최대 30초, 60초 넘는 공백은 0초다. 같은 프로젝트·30초 구간은 DB unique로 한 번만 기록한다. 다른 탭·세션·조직, 잠금 만료, 읽기 전용은 기록할 수 없다.

이 값은 청구할 노동시간이나 정확한 인간 편집 시간이 아니다. 브라우저 종료·숨김·네트워크 차단·짧은 작업은 누락될 수 있고 클라이언트 신호를 독립적으로 사실 확인하지 않는다. UI는 **활동 추정**과 **관측 없음**을 구분한다.

## 원가와 지원 시간

`/admin/metrics`는 관리자만 볼 수 있다. 제공자 요청별 model, 요청/응답 quality, 요청 크기, 상태, 오류 코드, 비용 근거를 보여준다. 프롬프트·디자인 내용은 반환하지 않는다.

- `actual`: 제공자 기록의 확인 비용 또는 관리자가 근거를 적은 확인 금액.
- `estimate`: 토큰/가격표 기반 제공자 추정 또는 관리자가 근거를 적은 추정 금액.
- `unknown`: 금액 null. **0원으로 합산하지 않는다.**
- `not_called`: 외부 호출 전 취소가 확인된 시도. 표시상 0이며 제공자 청구 원가 합계에서 제외한다.
- `fixture`: 합성 검증 시도. 실제 제공자 원가에서 제외한다.

제공자 재시도·실패·사용자 환불 후 늦은 결과의 원가도 원본 ProviderAttempt를 그대로 읽는다. 사용자 크레딧 원장을 원가로 사용하지 않는다. KRW/USD를 환율 가정으로 합치지 않으며 실제·추정·불명도 별도 합계다. 이미지 1장 200원 같은 고정 가정은 없다.

저장·출력·지원·PG 수수료는 `POST /v1/admin/metrics/costs`로 구분하여 기록한다. 금액 미확인 시 unknown/null로 남긴다. 지원 시간은 support 항목의 분 단위 별도 값이다. 현재 알려진 저장 객체 수·바이트와 출력 요청 수는 운영량이지 클라우드 청구 금액이 아니다. 삭제 완료 객체는 저장량에서 제외한다. 백업 사본·미참조 파일·보관 서비스 전체 청구를 의미하지 않는다. 결제별 수수료 기록이 없으면 수수료 미확인 건수로 표시한다.

비용 추가에는 관리자·CSRF·Idempotency-Key·사유가 필요하다. 프로젝트/작업/결제는 같은 조직 행이어야 한다. 수정·삭제로 과거 비용을 덮지 않고 `supersedes_id`로 최신 기록을 사유와 함께 정정한다. 정정 경합은 전역 DB gate + unique로 한 요청만 성공한다. `/admin/metrics/costs` GET의 페이지 이력은 정정 전 기록도 보여준다. 보고 합계는 현재 유효한 정정값만 사용한다. 사유에는 고객 문구·개인정보를 넣지 않는다.

최대 조회 기간은 366일이다. 표시 목록은 최신 100개 프로젝트/시도/유효 비용이며 합계는 표시 100개로 자르지 않는다. 소스별 집계 행 10,000개를 넘으면 잘린 숫자를 반환하지 않고 명시적으로 거절한다. 현재 저장 객체가 이 한도를 넘으면 별도 운영 보고서 추출이 필요하다.

## 배포·검증

`0017_metrics`는 `0016_font_assets` 뒤에 4개 새 테이블을 추가한다. 기존 프로젝트·결제·원장을 갱신하지 않는다. PostgreSQL RLS를 켜고 공개 정책을 만들지 않는다. 이 테이블을 사용하는 새 애플리케이션을 실행하기 전에 마이그레이션이 필요하다. rollback 시 새 계측 이력은 제거되지만 고객 원본 테이블은 보존된다. 보존할 운영 이력이 있으면 먼저 백업한다.

자동 검증: `services/api/tests/test_metrics.py`, `test_metrics_migration.py`, `apps/web/tests/acquisition.test.mjs`. 제조 worker 실제 격리 CMYK 성공/ICC 철회 시 이벤트 유무는 `tests/geometry_pdf/test_print_production.py`에서 확인한다. 검증은 합성 결제·주입 제공자·격리 DB만 사용하며 실제 결제, 유료 모델 호출, 운영 고객 삭제를 수행하지 않는다. 최신 실행 수치는 부모 릴리스 검증 보고에 합친다.

아직 없는 외부 실측은 실제 유료 고객 모집 결과, 공급자·클라우드 청구서 대사, 실제 지원 노동시간 측정, 실제 PG 수수료 확인, 제조사 10건 회신과 물리 출력 검증이다. 화면과 저장 구조를 구현했다고 이 목표가 달성됐다고 주장하지 않는다.
