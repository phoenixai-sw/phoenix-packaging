# 편집용 프로젝트 ZIP

`POST /v1/exports`에 `{project_id, base_revision, kind: "editable"}`를 보내면 기존 durable Job으로 처리한다. `Idempotency-Key`, CSRF, 활성 편집 lease는 기존 export 계약을 따른다. 응답의 `kind`는 `editable_export`이며 `/v1/jobs/{id}`에서 진행 상태를 조회한다. 성공 파일은 기존 `/v1/exports/{id}/download`, 실패 재시도는 `/v1/jobs/{id}/retry`를 사용한다.

이 작업은 무료다. 결제·크레딧 예약·원장 차감·제작 entitlement를 만들지 않는다. 검토 PDF와 합산해 조직당 시간당 30개 새 요청을 제한하며 검토·제작·편집 출력 전체에서 조직당 한 작업만 실행한다. 같은 키의 같은 요청은 기존 작업을 반환하고 다른 요청은 409다. 별도 권리확인 체크박스는 요구하지 않는다.

## 묶음 내용

- `project.json`: 프로젝트와 선택한 리비전 정보, 장면·도면·자산 목록 경로.
- `scene.json`: 저장된 모든 면과 객체. 숨김, 잠금, crop, 문구, 글꼴 두께, 가공, 샘플 바코드 및 미확인 정보도 그대로 보존한다.
- `geometry.json`, 해당하는 경우 `structure.json`: 요청 시 서버가 계산·보관한 구조. 이후 구조/장면 변경과 분리된다.
- `assets.json`, `assets/<UUID>.<확인한 확장자>`: 장면 자산과 참조·부모·최초 원본을 중복 없이 포함한다. 다시 인코딩하거나 자르지 않은 실제 바이너리다. 원본 파일명은 JSON 정보로만 보관하며 ZIP 경로로 사용하지 않는다.
- `fonts/`: 실제 사용 NotoSansKR 400/700 정적 파일, SIL OFL 1.1 전문 및 출처/변환 이력 README. 포함 전 서버 허용 목록과 배포 해시를 확인한다.
- `manifest.json`: 구성 파일의 byte 수와 SHA-256, 프로젝트/리비전, 포맷 버전, 폰트, 무료·검토 전용·권리 안내. manifest 자체의 해시는 외부 ZIP SHA에 포함된다.
- `README.ko.txt`: 파일 연결과 한계 안내.

AI 프롬프트, 제공자 원문, 토큰, 저장소 키, signed URL, 사용자 세션 정보는 공개 manifest에 포함하지 않는다. 화질 보완의 native 픽셀/확대·합성 도련 출처는 유지한다. 업로드 당시 해시가 없는 옛 자산은 파일 크기·형식·픽셀을 검증한 뒤 export 시 해시를 계산하며 `computed_at_export`로 구분한다. 업로드 시 해시가 있는 자산은 그 값과 일치해야 한다.

JSON은 Phoenix 장면 형식이다. Illustrator/Photoshop 형식이나 제조용 출력이 아니며, 현재 앱에 ZIP 재가져오기 화면은 없다. 전체 조직 데이터·모든 리비전 이력을 담은 운영 백업과도 별개다. 포함된 원본의 권리를 확대 부여하거나 제삼자 권리를 검증했다는 의미가 아니다. 이 안내는 요청·성공 감사 기록에도 남는다.

## 권한과 실패 처리

새 작업과 재시도는 owner/editor 및 현재 팀·프로젝트·개별 원본 workspace 권한을 요구한다. viewer의 새 출력은 거절한다. worker가 시작할 때와 공개 직전에 권한을 다시 확인하고, 최종 공개 동안 관련 행을 잠근다. 현재 프로젝트가 다음 리비전으로 편집되어도 요청한 저장본은 유지된다. 브라우저 편집 lease는 worker 실행에는 필요하지 않다.

다운로드는 현재 로그인·팀·프로젝트·묶음에 포함된 자산의 접근 권한을 검사한다. 유료 구독 종료 후에는 기존 정책대로 소유자는 자료를 사용할 수 있고 다른 팀원은 접근할 수 없다. 다운로드를 새 유료 제작 권한으로 취급하지 않는다.

자산당 64MiB, 원본 최대 2,000개, JSON 파일당 32MiB, 전체 비압축 자료 및 완성 ZIP 각각 256MiB를 제한한다. 원본 누락, 크기·해시·형식 불일치, 미허용 폰트, 저장 실패면 부분 묶음을 공개하지 않는다. 사용자에게 안전한 오류만 보여 주며 명시적으로 재시도할 수 있다.

각 worker lease는 독립 비공개 키에 쓴다. 결과 저장 후 다시 읽어 ZIP 해시를 확인하며, lease CAS에 성공한 작업만 공개한다. 철회/오래된 worker의 미공개 파일은 쓰기 전에 등록한 해당 lease intent로 남긴다. 새 보관 정책은 즉시 finally 삭제 대신 hold·백업·참조 보호를 확인하는 bounded GC를 사용하며 기본 실행은 꺼져 있다. DB commit 응답이 불확실한 경우 실제 성공 결과가 참조하는 파일은 보호한다. 알 수 없는 파일은 정리하지 않는다.

Hosted 다운로드는 60초 private signed URL로 307 응답한다. 폰트를 포함한 큰 ZIP 바이트가 Next/Vercel API 응답을 통과하지 않는다. 로컬 개발에서는 직접 파일 응답이다.

## 마이그레이션·보관

`0009_editable_exports`는 기존 `uq_running_export_tenant` 조건에 `editable_export`를 추가한다. 기존 장면·작업 JSON을 바꾸거나 기존 파일을 삭제하지 않는다. 배포 전 백업과 stage build를 준비하고, 검증한 hosted 설정으로 migration을 적용한 다음 API→웹 순서로 승격한다. 새 worker가 실행되는 동안 이전 인덱스로 downgrade하지 않는다. 후속 `0010`이 함께 배포된다면 전체 head를 적용한다.

기존 구독 서비스는 마지막 유료 기간 종료+90일과 구매분 만료 중 늦은 보관 시각을 계산한다. 앱 내 만료 예고와 보관·지원 화면이 연결되어 있다. 기한만으로 자동 삭제하거나 다운로드를 차단하지 않는다. 명시적 소유자 삭제 요청의 실행·유예·보호 범위는 [보관 운영 문서](retention-operations.ko.md)를 따른다.

## 검증 범위

`services/api/tests/test_editable_exports.py`는 실제 ZIP의 장면·이미지 bytes·폰트/OFL·SHA 일치, 다른 tenant에 바이너리와 JSON을 옮긴 뒤 저장/재열기, 원장 불변, 테넌트/워크스페이스/viewer/해지 권한, CSRF/lease/idempotency, 누락·손상·저장 실패와 재시도, 공개 전 권한 철회, 각 원본 권한 변경, 전체 크기 한도, worker 만료·복구, cross-kind 동시 실행, 무료 요청 제한, hosted 307, migration 보존을 검증한다. 운영 실제 다운로드 검증은 배포 후 별도로 기록한다.
